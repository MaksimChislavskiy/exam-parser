# Exam Parser

Пайплайн извлекает математические задачи из одного PDF или изображения страницы.

```text
PDF/изображение
      ↓
PaddleOCR-VL → Markdown + изображения
      ↓
DeepSeek или GigaChat → условия задач
      ↓
независимо настраиваемые результаты
      ├── подробное решение: выбранная LLM или пусто
      └── короткий ответ: выбранная LLM, документ или пусто
      ↓
tasks.xlsx + images/*.png
```

## Входные документы

Все исходники размещаются в стандартной папке:

```text
output/input/
```

В команде указывается только имя одного конкретного файла:

```powershell
uv run python main.py trvar540.pdf
```

Программа обработает только `output/input/trvar540.pdf`. Она не перебирает остальные
файлы в папке. Полный путь передавать не нужно и нельзя.

## Выбор LLM-провайдера

По умолчанию используется DeepSeek:

```powershell
uv run python main.py trvar540.pdf
```

GigaChat выбирается отдельным параметром:

```powershell
uv run python main.py trvar540.pdf --provider gigachat
```

Провайдера по умолчанию можно задать в `.env`:

```env
LLM_PROVIDER=deepseek
```

Поддерживаемые значения:

```text
deepseek
gigachat
```

Параметр `--model` относится к выбранному провайдеру.

## Настройка DeepSeek

```env
DEEPSEEK_API_KEY=ваш_ключ
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_TIMEOUT=180
DEEPSEEK_MAX_RETRIES=6
DEEPSEEK_MAX_TOKENS=16384
DEEPSEEK_REASONING_EFFORT=high
```

Для извлечения задач и готовых ответов клиент отключает thinking mode и просит
строгий JSON. Для генерации решений и ответов thinking mode включается с усилием
`high`.

Можно выбрать более дешёвую модель:

```powershell
uv run python main.py trvar540.pdf --provider deepseek --model deepseek-v4-flash
```

## Настройка GigaChat

Для физического лица с моделью GigaChat 3 Ultra:

```env
GIGACHAT_CREDENTIALS=ваш_ключ_авторизации
GIGACHAT_MODEL=GigaChat-3-Ultra
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_BASE_URL=https://api.giga.chat/v1
GIGACHAT_VERIFY_SSL_CERTS=true
```

`GIGACHAT_CREDENTIALS` — ключ авторизации из проекта GigaChat API, а не временный
access token. SDK самостоятельно получает и обновляет access token.

Для проверки TLS рекомендуется установить корневой сертификат НУЦ Минцифры и
указать путь:

```env
GIGACHAT_CA_BUNDLE_FILE=C:/path/to/russian_trusted_root_ca.pem
```

Временное отключение проверки сертификата возможно через:

```env
GIGACHAT_VERIFY_SSL_CERTS=false
```

Это снижает безопасность соединения и не должно оставаться постоянной настройкой.
Полный шаблон переменных находится в `.env.example`.

Установка зависимостей:

```powershell
uv sync
```

## Независимые флаги результата

Подробное решение и короткий ответ настраиваются отдельно.

| Команда | Подробное решение | Короткий ответ |
|---|---|---|
| `main.py FILE` | выбранная LLM | выбранная LLM |
| `main.py FILE --no-solutions` | пусто | выбранная LLM |
| `main.py FILE --document-answers` | выбранная LLM | из документа |
| `main.py FILE --no-solutions --document-answers` | пусто | из документа |
| `main.py FILE --no-answers` | выбранная LLM | пусто |
| `main.py FILE --no-solutions --no-answers` | пусто | пусто |

Программа не создаёт ненужный результат:

- полный цикл использует один запрос на решение и ответ;
- `--no-solutions` вызывает только короткий запрос за ответом;
- `--document-answers` извлекает короткие ответы из раздела ответов PDF;
- `--no-answers` не создаёт короткие ответы;
- `--no-solutions --no-answers` оставляет только задачи и изображения.

Флаги `--document-answers` и `--no-answers` взаимоисключающие.

## Примеры

Вариант 540 с подробными решениями и ответами DeepSeek:

```powershell
uv run python main.py trvar540.pdf
```

Тот же документ через GigaChat:

```powershell
uv run python main.py trvar540.pdf --provider gigachat
```

Вариант 951 с ответами из документа, без решений и без повторного OCR:

```powershell
uv run python main.py "ЕГКР Профиль 951 ФИПИ с ответами.pdf" `
  --provider deepseek `
  --no-solutions `
  --document-answers `
  --reuse-markdown `
  --output-dir output/result/951-deepseek
```

## Изображения задач

LLM получает имена изображений в Markdown, но итоговая привязка проверяется кодом.
Изображение принимается только тогда, когда оно действительно находится внутри
Markdown-блока соответствующей задачи.

Маленькие HTML-изображения с шириной не больше `5%` считаются служебными
значками и не попадают в итоговую папку задач. Это защищает от привязки логотипов,
значков предупреждений и декоративных элементов.

## Выбор GPU или CPU

По умолчанию Paddle запускается с `--device gpu:0`.

Если Paddle видит CUDA, OCR работает на GPU. В консоли выводятся реальные параметры:

```text
compiled=True/False, gpu_count=N, actual=gpu:0/cpu
```

Если GPU недоступен, программа предупреждает о медленной работе CPU и спрашивает:

```text
GPU недоступен: установленная сборка Paddle не видит CUDA.
PaddleOCR-VL может обрабатывать одну страницу на CPU десятки минут.
Продолжить на CPU? [y/N]:
```

- `y`, `yes`, `д` или `да` — продолжить на CPU;
- Enter, `n` или любой другой ответ — отменить запуск;
- `--device cpu` — сразу запустить CPU без вопроса;
- `--allow-cpu-fallback` — автоматически разрешить переход на CPU.

В неинтерактивном запуске программа не зависает в ожидании ввода. Без явного
разрешения перехода на CPU она завершится с понятным сообщением.

Для GPU нужна совместимая официальная сборка `paddlepaddle-gpu`. Обычный пакет
`paddlepaddle` обычно является CPU-сборкой.

## Повторный запуск без OCR

Для входного файла с одним вариантом создаются отдельные рабочие каталоги:

```text
output/work/<имя_файла>/pages/
output/work/<имя_файла>/markdown/
output/result/<имя_файла>/tasks.xlsx
output/result/<имя_файла>/images/
```

## Несколько вариантов в одном PDF

Если после OCR в документе обнаружено несколько экзаменационных вариантов,
каждый вариант обрабатывается независимо. Число страниц варианта не фиксировано:
границы определяются по заголовку вида `Вариант MA2510509` и признакам начала
новой работы. Если номер варианта OCR не прочитал, используются безопасные имена
`variant_1`, `variant_2` и так далее.

Например, для `36533_36533Z.pdf` результат будет иметь вид:

```text
output/result/36533_36533Z/
├── MA2510509/
│   ├── tasks.xlsx
│   └── images/
├── MA2510510/
│   ├── tasks.xlsx
│   └── images/
├── MA2510511/
│   ├── tasks.xlsx
│   └── images/
└── MA2510512/
    ├── tasks.xlsx
    └── images/
```

Проверка `--expected-tasks` применяется к каждому варианту отдельно. Обычный PDF
с одним вариантом сохраняет прежнюю структуру без дополнительного подкаталога.
При `--reuse-markdown` готовый Markdown также заново делится на варианты, поэтому
повторный OCR для изменения структуры результата не требуется.

Готовый Markdown можно использовать повторно:

```powershell
uv run python main.py variant_951.pdf --reuse-markdown
```

При сравнении провайдеров рекомендуется задавать разные итоговые папки:

```powershell
uv run python main.py variant_951.pdf `
  --provider deepseek `
  --reuse-markdown `
  --output-dir output/result/variant_951_deepseek
```

Если для выбранного документа готового Markdown нет, программа завершится с
сообщением и не создаст пустой результат.

## Продолжение после частичной ошибки

Если запуск сохранил часть решений или ответов в `tasks.xlsx`, обработку можно
продолжить без повторного извлечения заданий и без повторных запросов для уже
готовых полей:

```powershell
uv run python main.py trvar540.pdf `
  --provider deepseek `
  --reuse-markdown `
  --resume-results
```

Флаг `--resume-results`:

- требует существующий `tasks.xlsx` в выбранной итоговой папке;
- использует сохранённые номера и условия задач как контрольную точку;
- проверяет ожидаемое количество задач и наличие сохранённых изображений;
- пропускает задания, у которых уже есть решение и ответ;
- запрашивает только ответ, если решение уже сохранено;
- запрашивает только решение, если ответ уже сохранён.

Используйте этот режим только для продолжения того же документа в той же итоговой
папке. Для нового извлечения условий или сравнения провайдеров запускайте программу
без `--resume-results` и используйте отдельные итоговые папки.

Успешное извлечение условий автоматически сохраняется постранично в
`output/work/<pdf_stem>/extraction_cache`. Если более поздняя страница завершится
ошибкой, повторный запуск с тем же Markdown, изображениями, провайдером и моделью
возьмёт уже проверенные страницы из checkpoint и не отправит их в LLM повторно.
Страница записывается только после очистки, сверки точности условия и привязки
изображения; ошибочный или незавершённый ответ не кэшируется.

Чтобы намеренно пересчитать условия всех страниц и заменить успешные записи кэша,
добавьте `--refresh-extraction-cache`. Изменение Markdown, изображения, провайдера
или модели автоматически создаёт другой ключ и также приводит к новому запросу.

## Формат Excel

```text
task_num | condition | image_name | solution | answer
```

Столбцы `solution` и `answer` остаются в Excel всегда. При отключении результата
соответствующий столбец остаётся пустым.

Геометрические обозначения дополнительно нормализуются после ответа модели.
Например, неразмеченное `A2BB2` преобразуется в `$A_2BB_2$`, а существующий LaTeX
повторно не оборачивается.

Только подпункты `а)`, `б)` и следующие подпункты одной задачи записываются в
Excel как отдельные HTML-абзацы `<p>...</p>`, чтобы при импорте на сайт их текст
не сливался. Основной текст и условия без подпунктов остаются без HTML-тегов.

## Справка командной строки

```powershell
uv run python main.py --help
```

Основные параметры:

```text
FILE                     имя файла из output/input
--provider PROVIDER      deepseek или gigachat
--no-solutions           не создавать подробные решения
--document-answers       брать короткие ответы из документа
--no-answers             не создавать короткие ответы
--reuse-markdown         не запускать OCR повторно
--run-ocr                явно запустить OCR заново
--resume-results          продолжить по существующему tasks.xlsx
--device gpu:0|cpu|auto
--allow-cpu-fallback
--expected-tasks 19
--model MODEL
--output-dir PATH
--markdown-dir PATH
--pages-dir PATH
--dpi 300
```

`--expected-tasks 0` отключает проверку количества задач.
