# Внешнее хранилище данных и справочники

Проект постепенно отделяет код парсера от больших и изменяемых данных.
Справочники, датасет и кэш не должны быть зашиты в `markdown_pipeline.py` и не
должны зависеть от конкретной буквы диска.

## Data root

Корень внешнего хранилища задаётся переменной окружения:

```env
EXAM_PARSER_DATA_ROOT=E:/Kuzovkin-data
```

Если переменная не задана, для разработки используется `~/.exam-parser-data`
вне репозитория.

Ожидаемая структура:

```text
<EXAM_PARSER_DATA_ROOT>/
├── references/
│   ├── exams.csv
│   └── topics.csv
├── dataset/
└── cache/
```

`DataStore` только описывает расположение данных. Он не привязывает проект к
конкретному диску, ОС или предмету.

## Справочники

`reference_catalogs.py` загружает иерархические CSV через `CatalogSpec`.
Поэтому схема не зашита только под текущие два файла. Для нового справочника
достаточно описать:

- имя файла;
- колонку ID;
- колонку названия;
- колонку родительского ID.

Текущие спецификации:

```text
exams.csv:  id / name_of_Exam / parent_of_exam
topics.csv: id / name         / parent
```

Остальные столбцы CSV сохраняются в `raw` и могут быть переданы классификатору.
Загрузчик проверяет дубликаты ID, битые parent-ссылки и циклы дерева.

### Область классификации

Полный справочник может содержать категории разных предметов или разных типов
экзаменов. Перед отправкой в LLM нужно ограничивать его допустимой веткой дерева,
а не надеяться, что модель сама не выберет соседний предмет.

`ReferenceCatalog.subtree(root_id)` создаёт самостоятельный каталог из выбранного
узла и всех его потомков. Корень области становится корнем нового каталога, а
категории из соседних веток вообще не попадают в промпт и не проходят валидацию.

Для текущего ЕГЭ по профильной математике проверенные области такие:

```text
exams:  root_id=2  — математика профиль
topics: root_id=1  — Математика
```

Пробный CLI требует задавать область явно:

```text
python -m exam_parser.classification_cli tasks.xlsx --catalog exams --scope-root 2
python -m exam_parser.classification_cli tasks.xlsx --catalog topics --scope-root 1
```

Это интерфейс для проверки одного справочника без изменения Excel.

## Новый tasks.xlsx

Лист `Tasks` подготовлен к формату:

```text
task_num | condition | image_name | solution | answer | exams_id | topics_id
```

Старые пятиколоночные `tasks.xlsx` по-прежнему читаются, поэтому существующие
checkpoint-файлы не ломаются.

Также создаётся лист `about` со столбцами:

```text
class | year | date | topic | exam_id | title | code | source_name |
is_public | source_url | description
```

При перезаписи checkpoint уже заполненный лист `about` сохраняется.

## Классификация готового workbook

Классификация пока намеренно не встроена в OCR-пайплайн. Для уже готового
`tasks.xlsx` есть отдельная команда, которая получает оба ID и пишет результат
только после успешного завершения обеих классификаций:

```bash
uv run python -m exam_parser.classification_apply_cli \
  "output/result/.../tasks.xlsx" \
  --exams-scope-root 2 \
  --topics-scope-root 1
```

По умолчанию исходный файл не изменяется. Рядом создаётся:

```text
tasks.classified.xlsx
```

Другой путь можно задать через `--output`. Уже существующий файл результата не
перезаписывается без `--force`.

После проверки результата можно явно заменить исходный файл:

```bash
uv run python -m exam_parser.classification_apply_cli \
  "output/result/.../tasks.xlsx" \
  --exams-scope-root 2 \
  --topics-scope-root 1 \
  --in-place
```

Даже при `--in-place` сначала вычисляются и валидируются `exams_id` и
`topics_id`, и только затем workbook заменяется через временный файл. Ошибка
второй классификации не оставляет Excel наполовину заполненным.

Лист `about`, условия, имена изображений, решения и ответы переносятся в
результат вместе с новыми ID.

## Следующий этап

После проверки отдельной команды классификацию можно подключить к основному
пайплайну. Корни допустимых областей должны определяться из метаданных экзамена,
а не вводиться пользователем вручную. OCR, классификация и Excel-экспорт при этом
остаются отдельными слоями.
